# Data Model: Sketch Runner

**Feature**: [spec.md](spec.md) | **Research**: [research.md](research.md)

Server state is minimal: one table and two blob prefixes. Gameplay state lives in the browser and is not persisted except the best distance.

## Server: `model_jobs` (Neon Postgres)

| Field | Type | Rules |
|---|---|---|
| `id` | uuid, PK | Generated by server |
| `access_token_hash` | text, not null | SHA-256 of the random token returned to the creator; token is the only way to read or cancel the job (no accounts) |
| `status` | enum: `queued`, `processing`, `ready`, `failed`, `timed_out`, `cancelled` | Initial `queued`; transitions below |
| `input_key` | text, not null | Blob pathname of the prepared image |
| `model_key` | text, null | Blob pathname of the model file; set only when `ready` |
| `failure_reason` | text, null | Player-facing message from a fixed list (no internal details) |
| `requested_at` | timestamptz, not null | Used for the 10-minute deadline |
| `updated_at` | timestamptz, not null | |
| `ip_hash` | text, not null | Hash of requester IP for rate limiting; not the raw IP |

**Indexes**: `(status, requested_at)` for the timeout sweep; `(ip_hash, requested_at)` for rate limiting.

### Status transitions

```text
queued ──► processing ──► ready
  │            │
  │            ├──► failed        (service error; reason from fixed list)
  │            └──► timed_out     (now − requested_at ≥ 10 min)
  └──► cancelled                  (player cancels while queued or processing)
```

Rules:

- `ready`, `failed`, `timed_out`, `cancelled` are terminal. Retry creates a new job.
- A character has at most one job in `queued` or `processing` (FR-004 cancel/retry).
- Transitions happen with conditional updates (`WHERE status = $from`), so late workflow results cannot overwrite `cancelled` or `timed_out`.

## Blob (private store)

| Prefix | Content | Lifetime |
|---|---|---|
| `inputs/{job_id}.{ext}` | Prepared image (orientation fixed, resized) | Deleted after job reaches `ready`, or after 24 h for other terminal states |
| `models/{job_id}.glb` | Generated model file | Kept while the player may view it; deleted 7 days after `ready` |

## Browser (client)

### `Character` (in memory, per session)

| Field | Type | Rules |
|---|---|---|
| `sourceKind` | `upload` \| `drawing` | |
| `silhouette` | polygon or mask reference | Derived from the image; see game-rules contract |
| `heightUnits`, `widthUnits` | number | Normalized bounding box; after size cap applied |
| `sizeCapped` | boolean | True when FR-021 cap applied; shown to player |
| `sketchImage` | canvas or blob URL | Used for 2D mode |
| `jobId` | string, nullable | Set after job creation |
| `modelStatus` | mirrors `model_jobs.status` plus `none` | `none` before creation |
| `presentation` | `2d` \| `3d`, default `2d` | Chosen on mode screen (FR-009) |

**Validation**: `heightUnits` and `widthUnits` must be within the bounds in `game-rules.md`. A silhouette with a single component under the minimum area is rejected with the "draw or upload again" message (edge case: nearly blank drawing).

### `Run` (in memory)

| Field | Type | Rules |
|---|---|---|
| `distance` | number | Increases with time at current speed |
| `speed` | number | Ramps per `game-rules.md` |
| `state` | `running` \| `paused` \| `ended` | Auto-pauses on hidden tab (FR-020) |
| `character` | `{ mode: standing \| jumping \| sliding, y, vy }` | Transitions in `game-rules.md` |
| `obstaclesPassed` | number | |
| `outcome` | `crashed` \| `null` | |

### `Obstacle` (in memory)

| Field | Type | Rules |
|---|---|---|
| `kind` | `ground_gap` \| `overhead` \| `pinch` | |
| `x` | number | Position along the run |
| `width` | number | Gap width (ground, pinch) or barrier length (overhead) |
| `clearance` | number | Overhead only: height from ground to the bottom of the barrier |
| `gapWidth` | number | Pinch only: horizontal opening |

### `BestScore` (localStorage)

| Key | Value | Rules |
|---|---|---|
| `sketchRunner.best` | JSON `{ distance: number, achievedAt: ISO string }` | Read/write wrapped in try/catch; on failure, treat as empty and keep playing (FR-026) |
| `sketchRunner.jobToken:{jobId}` | string | Token for resume and cancel; cleared when the job is terminal |

## Relationships

- One `Character` has zero or one active `model_jobs` row on the server (matched by `jobId`).
- One `Run` uses one `Character` and one `presentation`.
- `BestScore` is per device, not per character (FR-026).
